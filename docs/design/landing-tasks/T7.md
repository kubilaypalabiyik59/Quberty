# Task T7 — permanent Playwright spec for the landing page

Create exactly one file, and nothing else:

- `frontend/tests/e2e/11-landing.spec.ts`

## What already exists (do not modify)

- `playwright.config.ts` sets `baseURL: 'http://localhost:3000'`, so use relative paths such as
  `page.goto('/?lang=en')`.
- The dictionaries and constants must be imported with **relative** paths, because Playwright does
  not resolve the `@/` alias here:
  - `import { en } from '../../src/app/(landing)/i18n/en';` (`tr` and `es` the same way)
  - `import { DEMO_EMAIL, SECTION_IDS } from '../../src/app/(landing)/content';`
- `import { test, expect } from '@playwright/test';`
- Dictionary fields you will need: `t.meta.title`, `t.hero.title`, `t.hero.primary`,
  `t.problem.title`.
- The language switcher consists of three buttons whose accessible names are `EN`, `TR` and `ES`.
  The active one has `aria-pressed="true"`. Clicking one navigates to `/?lang=<code>` and sets a
  cookie.
- The landing root is a `<div lang="<code>">`.

## Rules for this file

- **Never type an expected text as a literal.** Always take it from the dictionary (for example
  `en.hero.title`), so that a copy change never breaks the test.
- Put everything inside one `test.describe('Landing page', () => { ... })`.
- Where a test repeats over languages or widths, generate the tests in a `for` loop, as in the
  example.

## Pattern — the first test, as an example

```ts
const DICTIONARIES = { en, tr, es } as const;

test.describe('Landing page', () => {
  for (const [lang, t] of Object.entries(DICTIONARIES)) {
    test(`renders in ${lang}`, async ({ page }) => {
      await page.goto(`/?lang=${lang}`);
      await expect(page.getByRole('heading', { level: 1 })).toHaveText(t.hero.title);
      await expect(page.locator(`div[lang="${lang}"]`).first()).toBeVisible();
      await expect(page).toHaveTitle(t.meta.title);
    });
  }

  // ...the tests below
});
```

## Tests to write (you write the code)

1. **renders in each language.** This is the example above; include it as shown.
2. **No horizontal scroll.** For every width in `[360, 768, 1440]` and every language, generate
   one test:
   - set the viewport to that width and a height of 900;
   - open `/?lang=<code>`;
   - assert that `document.documentElement.scrollWidth - window.innerWidth` is exactly `0`.
3. **The switcher persists the choice.**
   - Open `/?lang=en`, click the `ES` button, and wait for the URL to end in `?lang=es`. The h1
     must equal `es.hero.title`.
   - Then open `/` with no query parameter. The h1 must still equal `es.hero.title`, and the `ES`
     button must have `aria-pressed="true"`.
4. **Falls back to the browser language.** Create a new browser context with `locale: 'tr-TR'`
   (use the `browser` fixture) and open `/`. The h1 must equal `tr.hero.title`. Close the context
   at the end.
5. **Content is visible under reduced motion.** Create a context with `reducedMotion: 'reduce'` and
   open `/?lang=en`. Find the level-2 heading named `en.problem.title`.
   - **Pitfall:** Playwright's `toBeVisible()` passes even when an element has opacity 0, so it
     cannot catch this bug.
   - Instead, assert that the heading's **parent** element (`heading.locator('..')`) has CSS
     `opacity` equal to `'1'`, using `toHaveCSS`. Close the context at the end.
6. **The demo CTA mails the demo address.**
   - At a 1440 px wide viewport, open `/?lang=en`.
   - The first link named `en.hero.primary` must have `href` equal to `mailto:${DEMO_EMAIL}`.
   - Use the imported constant. Never type the address.
7. **The header anchors have targets.** At a 1440 px wide viewport, for each value of
   `SECTION_IDS`, the page must contain exactly one `section` with that `id` (`toHaveCount(1)`).

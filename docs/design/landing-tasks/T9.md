# Task T9 — scroll-driven landing stage, wired into the page

Create one file and edit one file, and touch nothing else:

- create `frontend/src/app/(landing)/_components/LandingStage.tsx`
- edit `frontend/src/app/(landing)/page.tsx`: render `<LandingStage />` where `<LoginStage />` is
  now, and swap the import accordingly. Change nothing else in the page.

## What already exists (do not modify)

- `@/components/brand/LoginStage` exports `LoginStage({ children?: ReactNode })`. This is the
  fixed brand stage with the photograph, beam, cube and dust. `children` are painted between the
  beam and the cube.
- `@/app/(landing)/_components/MosaicField` exports `MosaicField({ className?: string })`.
- `frontend/src/app/(landing)/_components/landing.module.css` exports two classes:
  - `scrollStage` goes on the wrapper. It derives every cube, photo and scrim value from two CSS
    variables on the same element, `--p` and `--q`.
  - `mosaic` goes on the `MosaicField`. Its opacity follows `--p`.
  - Import it as `import styles from './landing.module.css';`.
- From `framer-motion`, you need `motion`, `useScroll`, `useTransform` and `type MotionStyle`.

## LandingStage (client component)

- `'use client'` goes on the first line. It is a named export with a doc comment.
- Get `scrollY` and `scrollYProgress` from `useScroll()`.
- `--p` (hero progress) is `scrollY / (0.8 × window height)`, clamped to at most 1. It must not
  crash on the server, where `window` does not exist:

  ```ts
  const heroProgress = useTransform(scrollY, (y) =>
    typeof window === 'undefined' ? 0 : Math.min(y / (window.innerHeight * 0.8), 1),
  );
  ```
- `--q` (page progress) is `scrollYProgress` itself.
- Render a `motion.div` with `className={styles.scrollStage}`. Its `style` sets the two CSS
  variables from the motion values. TypeScript needs the cast:
  `style={{ '--p': heroProgress, '--q': scrollYProgress } as MotionStyle}`.
- Inside it, render `<LoginStage>` with `<MosaicField className={styles.mosaic} />` as its child.
- Nothing else. The component branches on no browser value, so the server and the browser render
  the same markup.

## 2. `frontend/src/app/(landing)/i18n/types.ts`

## 3. `frontend/src/app/(landing)/i18n/getLocale.ts`

`export function getLocale(searchParams: { lang?: string | string[] }): Locale`

It returns the first supported locale from these sources, in this order:

1. `searchParams.lang`. If it is an array, use its first element.
2. The cookie named `LANG_COOKIE`: `cookies().get(LANG_COOKIE)?.value`. Import `cookies` from
   `next/headers`; it is synchronous in Next 14.1.
3. The `Accept-Language` header, read with `headers().get('accept-language')` (`headers` also
   comes from `next/headers`):
   - Split the header on `,`. Each entry looks like `tr-TR` or `en;q=0.8`.
   - The weight is the `q=` value, defaulting to 1 when absent. If the value is not a number,
     treat the entry as weight 0.
   - Drop entries whose weight is 0.
   - Sort by weight, highest first. When weights are equal, keep the original header order (a
     stable sort).
   - Reduce each tag to its primary subtag, lower-cased: `tr-TR` → `tr`, `es-419` → `es`,
     `EN` → `en`.
   - Return the first entry that `isLocale` accepts.
4. Otherwise return `'en'`.

For steps 1 and 2, trim and lower-case the value, then check it with `isLocale`. An unsupported or
malformed value is skipped, never thrown on.

Keep the header parsing in a separate exported pure function:
`export function pickFromAcceptLanguage(header: string | null): Locale | undefined`.
`getLocale` calls it.

## 4. `frontend/src/app/(landing)/i18n/getDictionary.ts`

`export function getDictionary(locale: Locale): LandingDictionary`. It returns the object for the
locale from a `const DICTIONARIES: Record<Locale, LandingDictionary> = { en, tr, es }` map.
